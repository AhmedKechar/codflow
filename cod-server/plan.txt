## الخطة التفصيلية — فريق متخصص (Orchestrator Pattern)

---

### الفريق специалистов

| الدور | التخصص | الخبرة |
|---|---|---|
| **🛡️ الأمني** | Auth, RBAC, Security Hardening | 30+ سنة أمن سيبراني |
| **🗄️ قائد قواعد البيانات** | Schema, Migrations, D1 Performance | 30+ سنة تصميم قواعد بيانات |
| **⚙️ المعماري** | defineRoute, Server Architecture | 30+ سنة هندسة برمجيات |
| **📦 التكاملات** | DZVerify, Sendili, APIs خارجية | 30+ سنة تكامل الأنظمة |
| **🎨 الواجهة** | Dashboard UI, Storefront, i18n | 30+ سنة تصميم واجهات |

## المرحلة 4: D1 Performance (يوم 6)

### 👨‍💻 المسؤول: قائد قواعد البيانات

#### المهمة 4.1: فهارس جديدة

**ملف جديد:** `cod-server/src/db/migrations/0032_d1_performance_indexes.sql`

```sql
-- فهرس فريد على هاتف العميل
CREATE UNIQUE INDEX IF NOT EXISTS idx_customers_phone_unique
ON customers (store_id, phone);

-- فهارس Keyset pagination
CREATE INDEX IF NOT EXISTS idx_orders_keyset
ON orders (store_id, created_at DESC, id DESC);

CREATE INDEX IF NOT EXISTS idx_orders_status_keyset
ON orders (store_id, status, created_at DESC, id DESC);

-- فهرس جزئي للطلبات النشطة
CREATE INDEX IF NOT EXISTS idx_orders_active
ON orders (store_id, created_at DESC)
WHERE status NOT IN ('delivered', 'returned', 'cancelled');

-- فهرس جزئي للطلبات مع tracking
CREATE INDEX IF NOT EXISTS idx_orders_tracking
ON orders (store_id, tracking_number)
WHERE tracking_number IS NOT NULL;

-- فهرس لـ shipping profiles الافتراضية
CREATE INDEX IF NOT EXISTS idx_shipping_profiles_default
ON shipping_profiles (store_id, is_default)
WHERE is_default = 1;

-- فهرس لتاريخ حالات الطلب
CREATE INDEX IF NOT EXISTS idx_order_status_history_order
ON order_status_history (order_id);
```

#### المهمة 4.2: إصلاح N+1 في Products

**الملف:** `cod-shared/queries/products.ts`

**المشكلة:** `getAllProducts()` تسبب 301 استعلام لـ 50 منتج

**الحل:** استبدال الـ 6 استعلامات لكل منتج بـ batch واحدة:

```typescript
// بدلاً من N+1
const rows = await db.select({...}).from(products)...all();

// استخدام db.batch() لجمع جميع الاستعلامات
const batchResults = await db.batch(
  rows.flatMap(p => [
    db.select({ count: count() }).from(productVariants).where(eq(productVariants.productId, p.id)),
    db.select({ total: sum(productVariants.inventory) }).from(productVariants).where(eq(productVariants.productId, p.id)),
    db.select({ src: productImages.src }).from(productImages).where(eq(productImages.productId, p.id)).limit(1),
    db.select().from(productVariants).where(eq(productVariants.productId, p.id)),
    db.select({ count: count() }).from(reviews).where(eq(reviews.productId, p.id)),
    db.select({ avg: avg(reviews.rating) }).from(reviews).where(eq(reviews.productId, p.id)),
  ])
);
```

#### المهمة 4.3: إصلاح N+1 في Customers

**الملف:** `cod-shared/queries/customers.ts`

**المشكلة:** `getOrdersByCustomerId()` تسبب 51 استعلام لـ 50 طلب

**الحل:** استخدام JOIN بدلاً من N+1:

```typescript
// بدلاً من
const ordersWithHistory = await Promise.all(
  customerOrders.map(async (order) => {
    const history = await db.select().from(orderStatusHistory)
      .where(eq(orderStatusHistory.orderId, order.id)).all();
    return { ...order, statusHistory: history };
  })
);

// استخدم
const ordersWithHistory = await db.select({
  ...orderFields,
  statusHistory: sql`json_group_array(json_object(...))`
}).from(orders)
  .leftJoin(orderStatusHistory, eq(orders.id, orderStatusHistory.orderId))
  .groupBy(orders.id);
```
